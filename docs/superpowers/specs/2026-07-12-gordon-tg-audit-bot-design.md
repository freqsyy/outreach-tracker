# 🤖 Гордон — Аудит-бот в ТГ (Блок 3)

## Цель
Превратить готовый `audit_site.py` («ИИ-аудит сайта») в инструмент, которым
можно пользоваться прямо из Телеграма. Кидаешь URL → получаешь отчёт.

Один движок + 3 режима вывода (переключатель, не три копии кода):
1. **Личный помощник** — Назар кидает URL, получает отчёт + счёт цены. Только для себя.
2. **Публичный платный** — клиенты сами кидают URL, платят, получают отчёт. Бизнес
   с лимитами/защитой от злоупотреблений.
3. **Подпитка аутрича** — URL → отчёт + сайт падает в БД как `pending` с тёплым
   письмом (как делает `agent_scout`, но с готовым багом из аудита).

## Архитектура
Отдельный агент `audit_tg_bot.py`. Переиспользует:
- `audit_site.py` — ядро отчёта (уже готово);
- `audit_engine.py` — детекторы багов (через CDP 9222);
- `agent_scout.py` — `url_is_safe()` / `is_safe_domain()` (SSRF-гарды);
- мост ПК<->ТГ — приём URL и отправку отчёта.

### Вход
- Мост ловит URL в свободном тексте (детект `http(s)://`) ИЛИ команду
  `/audit <url>` + режим (`/audit personal|paid|outreach <url>`).

### Поток
```
URL из ТГ
  -> url_is_safe() / is_safe_domain()  (SSRF-гард из scout)
       нет  -> "URL небезопасен, не аудирую"
  -> cdp_alive()?  (Хром на 9222)
       нет  -> "Подними Хром (agent-browser --cdp 9222) и кинь снова"
  -> audit_site.py.run(url)  -> отчёт (markdown)
  -> ветвление по режиму:
       personal : отчёт + примерная цена в ТГ
       paid     : проверка лимита/оплаты -> отчёт в ТГ (+ счёт)
       outreach : track.py add (pending, tags audit-bot) + bug в notes
                  -> сайт готов к рассылке с тёплым письмом
```

### Режимы (конфиг)
- `AUDIT_BOT_MODE` (дефолт `personal`): `personal` | `paid` | `outreach` | `multi`.
- `multi` — даёт выбор кнопками/командой каждый раз.
- `paid`: `AUDIT_BOT_LIMIT_PER_DAY`, `AUDIT_BOT_PRICE` (текст счёта), счётчик в файле.

### Обработка ошибок
- SSRF: жёсткий отказ на loopback/private/creds/редиректы (как в scout).
- Хром мёртв: понятная инструкция, не мусор в ответ.
- `audit_site` вернул 0 багов: «чисто, багов не нашёл» — честно, без выдумок.
- лимит `paid` исчерпан: «лимит на сегодня вышел, пришли завтра/оплати».

### Тестирование
- `tests/test_audit_bot.py`:
  - SSRF-URL отвергается;
  - небезопасный домен (127.0.0.1) отвергается;
  - `build_report` на мок-результат аудита даёт markdown;
  - режим `outreach` кладёт запись в мок-БД со статусом `pending`.

## План реализации (коротко)
1. `audit_tg_bot.py` — парсинг URL + ветвление по режиму (переиспользуем гарды scout).
2. Хук в `bridge_poll.py` (детект URL/команды `/audit`).
3. Конфиг `AUDIT_BOT_*` в `.env`.
4. Режимы personal/paid/outreach.
5. Тесты.

## Примечание про риски (paid-режим)
Публичный платный бот — это уже бизнес: нужны оплата, защита от abuse, лимиты.
Делаем в последнюю очередь, поверх personal. personal+outreach можно сразу.

## Связи
- Переиспользует `audit_site.py`, `audit_engine.py`, гарды `agent_scout.py`.
- Зависит от моста ПК<->ТГ и живого Хрома на 9222.
