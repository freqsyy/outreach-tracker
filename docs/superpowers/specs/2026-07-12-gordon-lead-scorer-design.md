# 🧩 Гордон — Агент-скоринг лидов (Блок 1)

## Цель
Научить Гордона сортировать очередь рассылки по «горячести» лида: сначала шлём
самым перспективным сайтам, а не в порядке добавления. Балл живёт в БД, sender
читает его при выборе очереди. Офлайн — только данные, уже лежащие в `sites`,
без сетевых проверок (без риска бана/замедления).

## Архитектура
Отдельный агент (как принято в Гордоне): `agent_scorer.py`, пишет в БД через
`track.py`. Не ломает существующих агентов.

### Колонка БД
- Новая колонка `score REAL DEFAULT 0` в `sites`.
- Миграция идемпотентна (как `migrate_bounced_status`): детект по тексту CREATE,
  пересоздание таблицы только если `score` ещё нет. `PRAGMA journal_mode=DELETE`
  сохраняется (git-friendly sync).

### Факторы балла (сумма, max ~100)
| Фактор | Условие | Очки |
|---|---|---|
| Найден баг | `AUDIT::` в `notes` | +40 |
| Свежий домен | source содержит `fresh` ИЛИ возраст < 90д (из notes RDAP) | +25 |
| Есть Telegram | `telegram` не пуст | +15 |
| Источник scout | `source` = `scout` | +10 |
| Email на домене сайта | email оканчивается на домен из `url` (не gmail/yandex/mail) | +10 |
| Длина email-домена | бонус: длина > 10 символов | +5 |
- Сайты без бага/ТГ → низкий балл (0-20), но НЕ уходят в `review` (отсев — задача
  другого агента, здесь только приоритет).

### Компоненты
- `agent_scorer.py`:
  - `score_site(row) -> float` — чистая функция, легко тестить.
  - `run()` — читает все `pending` (+ можно `review`), считает, `UPDATE sites SET score`.
- `track.py`:
  - `score <id>` — пересчёт одного;
  - `score-all` — пересчёт всех (вызывает `agent_scorer.run`).
- `agent_sender.py`:
  - очередь `ORDER BY score DESC, created_at ASC` вместо текущей сортировки.
  - `send_now.py` — то же (он переиспользует логику очереди).

### Обработка ошибок
- `notes` пуст/битый → фактор бага = 0, не падает.
- миграция безопасна при повторном прогоне.
- не затрагивает статусы/отправленное — только `score`.

### Тестирование
- `tests/test_scorer.py`:
  - баг + ТГ + свежий scout → балл >= 80;
  - пустые данные → 0;
  - миграция идемпотентна (2-й запуск не ломает таблицу);
  - `agent_sender` строит очередь по `score DESC` (мок БД).

## План реализации (коротко)
1. Миграция `score` в `track.py` + `init_db`.
2. `agent_scorer.py` (функция `score_site` + `run`).
3. Подкоманды `score`/`score-all` в `track.py`.
4. Сортировка очереди в `agent_sender.py`/`send_now.py`.
5. Тесты.
