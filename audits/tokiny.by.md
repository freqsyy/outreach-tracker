## 1. КРИТИЧНЫЕ БАГИ (🔴 блокируют заказы = прямая потеря денег)

### #1 [CRITICAL] Скрытые обязательные поля телефона ломают форму заказа
- HTML: `<input id="telinputreg" type="tel" required>` + второе `<input type="tel" required>`.
- Оба поля **скрыты** от пользователя, но стоят `required` → браузер требует заполнить, форма не отправляется, ошибка юзеру не показывается.
- Источник: браузерный прогон Гордона 11.07 (`AUDIT::critical`).
- **Последствие:** заказ/регистрацию невозможно завершить.
- **Фикс:** убрать `required` со скрытых полей ИЛИ сделать видимыми + нормальная валидация.

### #2 [CRITICAL] На проде висит ТЕСТОВЫЙ баннер
- Проверено: `https://tokiny.by/uploads/banners/banner_test.jpg` → **HTTP 200, 271 KB**, ссылка присутствует в HTML главной (`banner_test.jpg` найден в исходнике).
- Клиентам показывается тестовая картинка-заглушка вместо боевого баннера.
- **Фикс:** заменить на боевой баннер, убрать `_test`-ассеты из паблика.

## 2. СЕРЬЁЗНЫЕ (🟠)

### #3 [HIGH] Сайт не адаптивен — отсутствует `<meta name="viewport">`
- Проверено: тега `viewport` в `<head>` **нет** (grep по HTML — False).
- При этом в CSS **18 медиазапросов** (`max-width:900px/1180px/1340px`) и 180 `display:flex` — вёрстка сама по себе адаптивная.
- **Но без viewport** мобильный браузер рендерит страницу как десктоп ~980px и сжимает её. Результат: на телефоне сайт показывается уменьшенным, зумить пальцами.
- **Последствие:** для доставки еды (большинство заказов с мобилки) — падает удобство и конверсия.
- **Фикс:** добавить `<meta name="viewport" content="width=device-width, initial-scale=1">`. ОДНА строка.
- ПРИМЕЧАНИЕ: визуальный скриншот мобильной версии не делался (браузерный движок не поднимался) — утверждение про "кнопки не нажать" НЕ проверено, в отчёт не включено.

### #4 [HIGH] Устаревший PHP 7.4.33 (End-of-Life)
- Заголовок ответа: `X-Powered-By: PHP/7.4.33`.
- Ветка 7.4 не получает патчей безопасности с 2022.
- **Фикс:** обновить до PHP 8.2/8.3, проверить совместимость плагинов Joomla.

### #5 [HIGH] Включён устаревший протокол TLS 1.1
- Проверено handshake: сервер принимает TLS 1.1, 1.2, 1.3.
- **Фикс:** в nginx отключить TLSv1/TLSv1.1, оставить TLSv1.2 + TLSv1.3.

## 3. СРЕДНИЕ / ТЕХНИЧЕСКИЕ (🟡)

### #6 [MEDIUM] Tailwind CSS через CDN в проде
- В HTML: `<script src="https://cdn.tailwindcss.com">`.
- В консоли браузера: `cdn.tailwindcss.com should not be used in production`.
- **Последствие:** медленнее, нестабильно, не для боевого использования.
- **Фикс:** собрать Tailwind через CLI/PostCSS → подключить готовый CSS.

### #7 [MEDIUM] Пустое мета-описание (SEO)
- `<meta name="description">` пустое (проверено).
- **Фикс:** добавить описание, напр. «TokiNY — доставка суши и азиатской кухни в Минске. Бесплатная доставка, свежие роллы, wok».

### #8 [MEDIUM] Нет кэширования
- Заголовки: `Expires: Wed, 17 Aug 2005 00:00:00 GMT` + `Cache-Control: no-store, no-cache`.
- Каждый визит грузит всё заново.
- **Фикс:** настроить Cache-Control для статики (CSS/JS/картинки на длительный срок).

### #9 [MEDIUM] 13 картинок без alt
- Проверено: все `<img>` без `alt`.
- Плохо для доступности и SEO-индексации изображений.

### #10 [LOW] Нет `lang="ru"` у `<html>`, нет аналитики (Метрика/GA)
- Клиент не видит откуда заказы и где бросают корзину. Рекомендуется Yandex.Metrika + цель на заказ.

### #11 [LOW] Раскрытие версий ПО в заголовках
- `Server: nginx/1.20.2`, `X-Powered-By: PHP/7.4.33`.
- **Фикс:** убрать `X-Powered-By`, в nginx `server_tokens off;`.
